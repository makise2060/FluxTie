# FluxTie 个性化（外观）设置页重构方案

> 基准：[Lingyan000/fluxdo](https://github.com/Lingyan000/fluxdo) 的外观设置体系（全量优先按 fluxdo 来，因其更现代、更美观）。
> 原则：**只移植设计与交互，不移植代码**（fluxdo 是 Flutter；FluxTie 是 Android Compose）。

---

## 一、结论先行

1. fluxdo 是 **linux.do（Discourse）的 Flutter 客户端**（非贴吧客户端），但其外观设置是完整的现代 Material 3 Expressive 体系，可直接作为设计蓝本。
2. fluxdo 最值得抄的是**四件事**：
   - **三层架构**：设置项声明（数据）→ 渲染器（UI）→ 通用页面脚手架，入口页只有 20 行；
   - **分段卡片视觉**（SegmentedCardGroup）：仿 Android 13+ 系统设置，每条目独立圆角块，取代"整卡 + Divider"；
   - **全即时预览**：主题模式三卡实时预览、色卡即预览、全项改即生效；
   - **主题合成器**：`ThemeState` + 纯函数 `resolve()` 双路径（彩色/中性解耦），带缓存的 seed 配色。
3. FluxTie 现状是"两页分散 + 平铺开关"：`CustomSettingsPage`（10 项平铺）与 `AppThemePage`（主题页，入口还藏在「我的」页），需要合并为单一「外观」页并按 fluxdo 分组重构。
4. **最大的技术约束**：FluxTie 用的是 **Compose Material 2**（`compose.material`）+ 自定义 `ExtendedColors`，不是 M3。fluxdo 的视觉全部可在 M2 基座上用 `Surface + Shape + Canvas` 复刻；但 seed→完整色板 需要 [material-color-utilities](https://github.com/material-foundation/material-color-utilities)（jitpack 可引）。**不建议本次重构同时迁移 M3**——那是另一个量级的工程。

## 二、fluxdo 设计要点提炼（移植目标）

### 2.1 三层架构

| 层 | fluxdo 实现 | 职责 |
|---|---|---|
| 声明层 | `lib/settings/settings_model.dart` sealed class（`SwitchModel`/`SliderModel`/`ActionModel`/`CustomModel`…，每项带 `id/title/subtitle`） | 设置项=数据，供搜索/跳转/高亮 |
| 渲染层 | `lib/settings/settings_renderer.dart`，按类型分派到对应 Tile | 单一渲染入口 |
| 页面层 | `lib/widgets/settings/settings_group_page.dart` 通用脚手架 | 分组渲染、高亮定位、隐藏项过滤 |

外观页入口 `lib/pages/appearance_page.dart` 仅 20 行：`SettingsGroupPage(title: 外观, groupsBuilder: buildAppearanceGroups, highlightId)`；全部条目声明在 `lib/settings/definitions/appearance_defs.dart`。

### 2.2 外观页 IA（分组与条目全清单）

| # | 分组 | 条目 | 形态 |
|---|---|---|---|
| 1 | 语言 | 跟随系统/简中/繁台/繁港/EN | 行 → 底部弹层单选 |
| 2 | 主题模式 | 自动/浅色/深色 | **三张迷你屏幕预览卡**并排（自动卡=左亮右暗分裂预览，随中性/纯黑开关实时变色） |
| 3 | 表面质感 | 中性（表面不染色）/ 纯黑（AMOLED） | 2 个开关 |
| 4 | 自定义背景 | 透明开关（无图自动拉相册）→ 展开背景图缩略图+更换、遮罩透明度滑杆（明暗分记）、模糊滑杆 0~20 | Custom 区块 |
| 5 | 主题色彩 | 配色风格横向滚动条（9 种 variant 预览卡）+ 色卡网格（动态取色卡带 ✨ 角标、14 内置色板、自定义色可长按删除、"+"添加 HSV 取色弹层） | Custom 区块 |
| 6 | 应用图标 | 经典/现代 预览卡切换（带 loading/失败 toast） | 双卡 |
| 7 | 字体 | 系统默认/MiSans（label 用该字体渲染，所见即所得） | 单选 |
| 8 | 屏幕帧率 | 自动/120Hz（异步枚举支持档位） | 行 → 底部弹层 |
| 9 | 卡片样式 | 实时预览 + 字号滑杆(带重置) + 头像排列 + 可精简字段开关 | 子页 |
| 10 | M3E 组件风格 / 对话框模糊 | 开关 | 2 行 |

设置首页：圆角搜索框 + 单列分类卡（彩色圆角图标块），点击进入子页；搜索从声明层自动建索引，点击结果**跳页并高亮定位**（`highlightId` → 滚动到位 + 2 秒高亮渐隐）。

### 2.3 视觉核心：SegmentedCardGroup

仿 Android 13+ 系统设置：**组内每条目独立成块**，块间缝 3dp，组首大圆角 20 / 中间 5 / 组尾大圆角 20；每条目前置彩色圆角图标块，开关开启时图标染 primary 色。

### 2.4 交互细节（全部要移植）

1. 全部设置**即时生效**，无"需重启"；
2. 预览卡实时反映当前主题状态（拨开关预览跟着变）；
3. 色卡=上 70% 主色填充 + 下 30% 三圆点（primary/secondary/tertiary），选中态描边+勾；选中前就能看到该色在当前风格下的效果；
4. 取色器：HSV 底部弹层 + HEX 输入双向同步 + 迷你实时预览；
5. 依赖隐藏：前置开关关闭时整行隐藏（`enabledWhen`）；
6. 滑杆值≠基准时显示"重置"按钮；
7. 触感反馈（每次切换 `selectionClick`）；
8. 底部弹层统一外壳（drag handle + 圆角）；
9. 性能三件套：seed 配色进程级缓存（64 条 LRU）、进入设置页 idle 预热、预览假数据实例稳定。

### 2.5 主题合成器

- `ThemeState`（不可变，13 字段：mode/neutral/black/transparent/accentSource/paletteId/seedColor/variant/customColors/…），每个 setter 即改即存；
- `resolve()` 纯函数一次解析明暗两套：**彩色 role（种子生成）× 中性层（无色相灰阶，亮/暗/纯黑/透明四套静态值）解耦**；
- 动态取色（Material You）**只取系统 primary 当种子**，不用 OEM 原始 scheme；
- `ColorScheme.fromSeed` 带 LRU 缓存，key=(种子, 亮暗, variant)。

## 三、FluxTie 现状诊断

### 3.1 页面与 IA 问题

- **两页分散**：`ui/page/settings/custom/CustomSettingsPage.kt`（个性化：字体大小/夜间模式主题/应用图标/主题图标/跟随系统夜间/状态栏加深/顶栏主题色/吧列表单列/隐藏动态入口/底栏上浮，共 10 项平铺）+ `ui/page/settings/theme/AppThemePage.kt`（动态取色横幅/自定义颜色/透明主题/8 固定主题）。
- **入口割裂**：主题页不在设置 hub 里，唯一入口在「我的」页（`UserPage.kt:357`）；字体大小还跳到遗留 View Activity（`AppFontSizeActivity`）。
- **视觉老旧**：`PrefsScreen` 平铺 + 1dp Divider，无分组卡片、无预览。

### 3.2 基建现状（可复用）

| 设施 | 现状 | 复用度 |
|---|---|---|
| Prefs DSL | `ui/common/prefs/`：`PrefsScreen`(LazyColumn+Divider)、`SwitchPref/ListPref/SliderPref/EditTextPref…`、`PrefsScope.prefsGroup{}` 分组已有 | DSL 保留，但渲染层要换成分段卡片 |
| 状态存储 | DataStore + `AppPreferencesUtils`（`appPreferences` 委托，key=属性名） | ✅ 直接沿用，key 全兼容 |
| 取色器 | godaddy `compose-color-picker` 0.7.0（AppThemePage 已用 HarmonyColorPicker）+ jaredrummler（View 端） | ✅ Compose 端已有 |
| 主题机 | `ThemeUtil`（字符串主题 id + `themeState`）、`ExtendedTheme.colors`（28 字段）、动态取色 `DynamicTonalPalette`（Android 12+ 系统色板）、View 端 `App.ThemeDelegate`（`theme_color_primary_$theme` 资源命名约定 + custom/translucent 特判） | 部分重构（见 §5.4） |
| 遗留包袱 | `LocalPrefsDataStore` 为 `lateinit var`（`PrefsScreen.kt:19`）——重设计时顺手修掉；透明主题走独立 Activity（`TranslucentThemeActivity`） | 替换 |

### 3.3 关键约束

1. **Material 2 基座**：`MaterialTheme.colors` 是 M2 API；fluxdo 的 M3 色彩体系（`ColorScheme.fromSeed`、`DynamicSchemeVariant`）需经 material-color-utilities 移植为"生成 `ExtendedColors`"的内部实现，**对 UI 层仍暴露 M2 + ExtendedColors**。
2. **双轨主题**：Compose 侧 `TiebaLiteTheme` 与 View 端 `ThemeDelegate`（遗留对话框/设置 Activity）必须同步更新，新增能力（seed 色）至少要让 View 端拿到 toolbar/primary 两色。
3. **动态取色已有**：`DynamicTonalPalette.kt` 已从系统 tonal 色读值——fluxdo"只取 primary 当种子"的方案可无缝接入。
4. **路由**：compose-destinations 按函数名生成 route；合并页面时保留旧 Destination 作为兼容跳转或删除引用（全仓库仅 `UserPage` 一处引用主题页）。

合并 `CustomSettingsPage` + `AppThemePage` 为单一 `AppearancePage`（route 保留 `custom_settings_page` 兼容，`app_theme_page` 重定向），按 fluxdo 分组（✅=现有 key 平移，🆕=新增）：

```
外观 (AppearancePage)
├─ 主题模式        自动/浅色/深色 三卡预览（🆕，替代现 follow_system_night + dark_theme 两项的割裂体验：
│                  浅色卡=当前浅色主题、深色卡=dark_theme 所选深色主题、自动卡=follow_system_night）
├─ 表面质感        纯黑 AMOLED 开关（✅ 即现 dark_theme=amoled_dark 的现代化表达：独立开关，

├─ 字体与显示      字体大小（🆕 SliderPref 0.8~1.3 步长 0.05 替代遗留 Activity，实时预览+重置）、
│                  状态栏加深（✅）、顶栏使用主题色（✅）
```

## 五、技术方案

### 5.1 设置项模型 + 渲染器（仿 fluxdo 三层）

新增 `ui/common/settings/`（与遗留 `prefs/` 并存，逐步替换）：

```kotlin
// SettingItem.kt —— 声明层
sealed interface SettingItem {
    val id: String                      // 供搜索/高亮定位
    val title: String
    val subtitle: String? = null
    // SwitchSetting(enabled: Boolean, checked, onChange)
    // ActionSetting(onClick, dynamicSubtitle: (() -> String)?)
    // ListSetting(options, selected, onSelect, useBottomSheet = true)
    // SliderSetting(range, steps, value, onChange, resetValue?)
    // CustomSetting(content: @Composable () -> Unit)   // 三卡预览/色卡网格等复杂区块
}
data class SettingGroup(
    val title: String, val icon: ImageVector?, val wrapInCard: Boolean = true,
    val items: List<SettingItem>,
)

// SettingRenderer.kt —— 渲染层
@Composable fun SettingRow(item: SettingItem, shape: Shape)   // shape 由分组位置算出

// SettingsGroupPage.kt —— 页面层
@Composable fun SettingsGroupPage(
    title: String, groups: List<SettingGroup>, highlightId: String? = null,
)   // LazyColumn + 分段卡片 + 组头(Icon+标题) + highlightId 滚动定位/高亮渐隐
```

### 5.2 分段卡片组件（视觉核心）

```kotlin
@Composable fun SettingBlock(items: List<SettingItem>, modifier: Modifier) {
    Column(verticalArrangement = Arrangement.spacedBy(3.dp)) {
        items.forEachIndexed { i, item ->
            Surface(
                shape = RoundedCornerShape(
                    topStart = if (i == 0) 20.dp else 5.dp, /* …四角同理 */
                ),
                color = ExtendedTheme.colors.card,
            ) { SettingRow(item, …) }
        }
    }
}
```
条目行：48~56dp 高，前置圆角图标块（开启染 primary/关闭 `textSecondary`），trailing 开关或 chevron；切换时 `LocalHapticFeedback.performHapticFeedback(TextHandleMove)`。

### 5.3 主题模式三卡预览 + 色卡网格

- **三卡预览**：`Canvas` 自绘迷你屏幕（顶条 + 两行文本线 + primary 按钮）；"自动"卡左右分屏亮/暗；**色值从当前 `ExtendedColors` + 候选模式实时解析**——拨动 AMOLED/中性开关，卡片同步变色。
- **色卡网格**：`LazyVerticalGrid`（或 FlowRow）列数 `max(3, width/88.dp)`；每卡 = 上 70% 主色块 + 下 30% 三圆点，选中态 2dp primary 描边 + 角标勾；动态取色卡左上 `auto_awesome` 角标；自定义色**长按出删除遮罩**；"+"卡打开 godaddy `HarmonyColorPicker` **底部弹层**（配 HEX 输入 + 迷你预览）。
- **固定主题**：8 个现有主题 id 映射为色板卡（种子色取 `theme_color_primary_$theme` 资源），点击仍走 `ThemeUtil.switchTheme()`——**数据层不动**。

### 5.4 主题引擎升级（分两步走）

**第一步（随本次重构，低风险）**：
- 抽 `ThemeState`（data class：theme id / darkTheme / followSystemNight / amoled / useDynamicColor / customPrimaryColor / toolbarPrimary…）+ `ThemeResolver` 纯函数，输出仍是 `ExtendedColors`；`ThemeUtil` 退化为持久化 + 状态发射器（保留 `themeState` 兼容现有调用点）。
- seed→色板：引入 `com.github.material-foundation:material-color-utilities`（jitpack），新增 `SeedPalette.generate(seed: Int, dark: Boolean)` 生成 primary/accent/tonal 桥接到 `ExtendedColors`；**带 (seed,dark) LRU 缓存（64 条）**。
- 动态取色对齐 fluxdo：Android 12+ 取系统 `accent1` 单色当种子 → `SeedPalette.generate`（替代/兼容现 `DynamicTonalPalette` 直读方案，开关 key `useDynamicColorTheme` 不变）。
- View 端兼容：`App.ThemeDelegate.getColorByAttr` 增加从 Resolver 缓存读值，保证遗留对话框不花屏。

**第二步（P2，可选）**：配色风格 variant（9 种 `DynamicSchemeVariant`）、中性表面解耦（彩色/中性 role 分离，需扩展 `ExtendedColors` 或新增 surface 色 group）。

### 5.5 自定义背景（透明模式现代化）

- 用 Compose 全局背景层替代 `TranslucentThemeActivity`：在 `MainActivityV2` 内容根部垫 `AppBackgroundLayer`（图片 cover + 明暗自适应遮罩 + `Modifier.blur()`/`RenderEffect` 高斯模糊），`scaffoldBackgroundColor` 透明化由现有 `translucent` 主题路径承接；
- key 沿用 `translucent_*` 系列并新增 `bg_scrim_light/bg_scrim_dark/bg_blur`；开开关无图时直接拉起图片选择器（复用现有 matisse/PhotoPicker 链路）。

### 5.6 设置搜索（P2）

- `SettingItem.id/title/subtitle` 自动建索引（纯内存 List 过滤即可，无需倒排）；
- 结果页点击 → `SettingsGroupPage(highlightId = id)`：`LazyListState.animateScrollToItem` + `AnimatedVisibility` 高亮 2s 渐隐。

### 5.7 数据与兼容性

- **所有现有 DataStore key 不改语义**：`theme/dark_theme/follow_system_night/custom_primary_color/useDynamicColorTheme/app_icon/useThemedIcon/status_bar_darker/custom_toolbar_primary_color/listSingle/hideExplore/liftUpBottomBar/fontScale` 全部平移到新分组；新增项用新 key。
- `AppThemePageDestination`/`CustomSettingsPageDestination` 保留 route，内部 302 到新页（或直接改 `UserPage` 引用并删除旧页——仅 1 处引用）。
- 遗留 `AppFontSizeActivity` 在新字体滑杆落地后删除（同步清 `goToActivity` 引用）。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| M2 基座无法直接用 M3 色彩 API | MCU 是纯 Java 无 UI 依赖，只在其上封 `SeedPalette`；UI 仍走 ExtendedColors，不强制迁移 M3 |
| 双轨主题失同步（Compose vs View ThemeDelegate） | Resolver 为唯一色源，View 端改为读缓存；`status_bar_darker`/`custom_toolbar_primary_color` 逻辑收敛进 Resolver |
| 三卡/色卡每帧多次配色卡顿 | (seed,亮暗) LRU 缓存 + 进入外观页 idle 预热（学 fluxdo AppearanceWarmup）+ 预览假数据 `remember` 稳定实例 |
| compose-destinations 路由破坏 | 保留旧 route 兼容；全仓库引用点仅 `SettingsPage`/`UserPage` 两处，编译期即可发现 |
| `LazyVerticalGrid` 嵌套在设置 LazyColumn 中 | 色卡网格用 `FlowRow` 或固定行高的"网格条"实现，避免嵌套滚动 |
| fluxdo 的 M3E 动效（按钮形变/year2023 滑轨） | 依赖 M3 组件库，**不移植**；仅保留视觉与交互，动效用现有 anim 体系近似 |
